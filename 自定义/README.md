# 自定义套图

`自定义/` 是 AI 生成的《鹅鸭杀》自定义套图汇总目录，成品最终用于微信小程序里的角色图标。**一个子文件夹 = 一套风格**，文件夹名即风格名。本文只说明目录用途和设计底线，不逐一列举已有套图，也不规定具体设计方向。

## 目录结构

```
自定义/
├── README.md
├── <风格名>/                     # 一套完整的自定义风格套图
│   ├── goose/goose_<角色名>.png
│   ├── duck/duck_<角色名>.png
│   └── neutral/neutral_<角色名>.png
└── <主题素体>.png                # 主题参考图，不是成套成品
```

- 完整一套按官方 56 个角色组织：鹅 24、鸭 23、中立 9。
- 阵营目录与文件名严格对齐 `official_camps_v3/`，格式为 `<阵营>_<角色名>.png`，方便与官方图逐张对照、整批替换。
- 根目录的单张 PNG 是生成主题套图用的素体/参考图，不代表一套成品；成套成品只放在子文件夹内。
- 文件夹使用语义化风格名（如「手绘」），禁止 `v1`、`v2`、`副本`、`final` 之类的命名。
- 个别套图目录内可能保留该套的任务 JSON 作为存档，这不属于规范要求；生图过程文件以工坊批次为准。

## 设计规范

> 这些规范只约束「识别度」和「产物管理」，不约束画风、构图、信息密度等具体设计选择。具体方向由 AI 结合主题发散、由用户确认。

### 1. 先分析，再设计

每个新套图、每个候选方向在写 prompt 前，先做一次识别分析：

- 打开 `official_camps_v3/` 对应实图，逐项列出画面里可能承担识别作用的元素：轮廓、阵营色、头部/身体特征、标志性道具或徽章、表情、纹样、构图语言等。
- 逐个判断这些元素与官方素材的联系有多强、以什么方式体现，在小尺寸下是否还成立；哪些适合保留，哪些适合简化、夸张或转译，哪些可以舍弃。
- 结合当前主题，说明本套准备用哪些元素、如何组织，再开始写 prompt。

分析结论决定设计，不套模板；不预设元素数量，也不规定必须保留哪几类。

### 2. 以官方 logo 为识别锚点

- 唯一权威参考是 `official_camps_v3/`（官方 56 角色基准图）。不凭记忆、不引用旧档案。
- 可以换画风、材质、主题服装，也可以重新组织构图，但最终要让小程序用户一眼把这张图和官方角色对上号。认不出是谁，设计再好看也不算合格。

### 3. 生成产物统一落工坊

- 生图任务 JSON、全部原图、画廊/预览 HTML 一律放 `工坊/批次/YYYYMMDD_语义名/`；输出路径写绝对路径，指向该批次的 `images/` 子目录。
- `自定义/` 只放经过人工挑选、压缩后的成品套图；候选图、废稿、中间产物不进来。
- 从批次转成品时保持目录结构与命名不变，按风格整文件夹归档，方便分类和后续替换。

### 4. 简约与丰富由设计目标决定

- 不设元素数量上限，也不要求「只留一个角色一个道具」。简洁不是删到最少，丰富也不等于堆砌；判断标准是每个元素是否在服务角色识别和主题表达。
- 是否使用场景、多个角色、文字、装饰、光影，由该套的设计概念决定；只要有助于表达「这是谁、这是什么主题」，就可以用。
- 用微信小程序的实际显示尺寸做检验：缩到 128×128 或九宫格大小时，主体是否清楚、角色是否还能认出。不清楚时优先调整构图、对比和主次关系，而不是机械删元素。
- 不同套图可以有不同的信息密度和设计手法，不必统一成同一种模板。

### 5. 每套风格独立发散

- 新套图从主题和官方角色本身重新构思，**不要参考已有套图**的画风、构图、配色或设计方向，也不要延续上一套。
- 用户让选方向时，AI 结合主题主动发散，给出彼此差异明显的候选方向，并说明每个方向与官方素材的关联方式；由用户拍板。
- 不预设固定套路。每套的设计逻辑应能自己成立，而不是把上一套的成功做法换个主题再用一遍。

### 6. 参考图：非必要不用

- 默认零参考图，用文字 prompt 锁死画风、官方角色特征和构图。部分生图模型对参考图保持过强，会把参考图的姿势、构图、背景一起复制，导致整批图千篇一律。
- 只有在确实需要锁定某个具体形象（如主题素体的人脸/发型，或官方徽章的精确几何）时才加参考图；能用文字描述清楚的，就不加图。
- 确需参考图时，只挂对应角色的官方图或主题素体；禁止把同批已生成的成图当第二参考图。
- 用了参考图要在 prompt 里明确「只保留什么、其余全部重新设计」，并在出图后检查整批是否构图雷同。
- 参考图路径写绝对路径，Windows 反斜杠在 JSON 中需要转义。

## 新增一套的流程

1. **定主题、定方向**：AI 先做官方识别元素分析，结合主题发散候选方向，用户确认后再开工。
2. **建批次**：`工坊/批次/YYYYMMDD_语义名/`，并在 `工坊/_台账.md` 登记一行。
3. **写任务 JSON**：字段按 `TASKS_JSON_FORMAT.md`；默认零参考图，确需时只用官方图或主题素体；写完跑关键词断言与 `--dry-run` 自查。
4. **跑批看画廊**：由用户在 `image_gallery.html` 中挑图；落选图保留在批次内，不删不改。
5. **转成品**：成品压缩后复制到 `自定义/<风格名>/`，按官方 56 角色结构补齐，并更新批次 README 与台账。
